# Fix: Duplicate project

## Why it fails
The project list loads each project together with its photo list (to show the cover thumbnail). The Duplicate action copies the whole loaded row, including that photo list, into the new project. The database has no such column on projects, so it rejects the insert and nothing is created.

## Fix (one action in the project list only)
- Build the new project from an explicit list of fields only: title_bg, title_en, description_bg, description_en, category, area_m2, location, completion_year, design_style, client_tags, display_order.
- Titles copied unchanged (no "(copy)" added) — the requirement says copy all fields as-is.
- status set to draft; new id generated by the database.
- New slug: `original-slug-copy`, then `-copy-2`, `-copy-3`… until unique (existing helper). If two clicks race and the slug collides, retry once with the next suffix; otherwise show the duplicate-slug error.
- No photo records or files copied; the original project is never touched.
- Single insert, so either the full duplicate is created or nothing is.
- On success: success message, refresh the list, then open the new project's edit page (same as after creating a project).
- On failure: clear error message, nothing created.

## Not changed
Database, security rules, storage, public site, logos, favicon, Netlify/build settings, and all other admin actions.
